# Development

## Repository layout

```text
src/ConstantProxy.Core/             pure logic (net8.0)
src/ConstantProxy.Infrastructure/   processes, sockets, SQLite, files (net8.0)
src/ConstantProxy.App/              WPF application (net8.0-windows)
tests/ConstantProxy.Tests/          xUnit tests, no GUI dependency (net8.0)
assets/                             application icon (generated by scripts/make_icon.py)
docs/                               architecture, configuration, development, releases
scripts/                            helper scripts
.github/workflows/                  build.yml, release.yml
Directory.Build.props               the single source of the version and shared compiler settings
global.json                         pins the .NET SDK band
```

## Prerequisites

- .NET 8 SDK (`dotnet --version` ≥ 8.0.100).
- Windows 10/11 to *run* the application. The libraries and every test run on Windows, Linux and macOS.

## Everyday commands

```bash
dotnet restore
dotnet build -c Release                     # whole solution (Windows; also compiles the WPF project on Linux/macOS)
dotnet test tests/ConstantProxy.Tests       # unit tests (any OS)
dotnet publish src/ConstantProxy.App -c Release -r win-x64 --self-contained true \
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtraction=true -p:EnableCompressionInSingleFile=true
```

`EnableWindowsTargeting` is set in `Directory.Build.props`, so the WPF project can be *compiled and published* on a
non-Windows host (useful for CI-like checks). It cannot be *run* there.

Warnings are errors in Core, Infrastructure and the tests (`TreatWarningsAsErrors`); nullable reference types are on
everywhere. The App project is excluded from warnings-as-errors because of generated XAML code.

## Conventions

- Prefer small classes, explicit state, nullable annotations, `async`/`await` with cancellation tokens.
- No static global state (the XAML localization bridge is the one deliberate exception), no `Thread.Sleep` in async flows,
  no swallowed exceptions: every `catch` names the exceptions it expects and either logs or explains why ignoring is safe.
- UI code must not contain networking or process logic; view models talk to `ConnectionManager` and services only.
- Keep dependencies minimal. The only external package is `Microsoft.Data.Sqlite`.
- Never hardcode deployment values (hosts, ports, paths, timings). Defaults live in the models and are all configurable.

## Testing strategy

Everything that can be tested without a Windows desktop is tested without one:

| Area | How |
| --- | --- |
| State machine | exhaustive transition-table test |
| `ConnectionManager` | fakes for launcher/verifier/probes/monitor + `FakeClock`; scenarios for double connect, disconnect during connect/reconnect/delay, manual reconnect, backoff, healthy reset, permanent failures, health degradation; a randomised stress test asserts no two ssh processes are ever alive |
| ssh arguments | exact expected lists (including the specification example) |
| Reconnect / health / traffic math | pure unit tests |
| Process launching | real child processes (`sleep`, `ping`, `sh`) — output capture, exit codes, no shell interpretation |
| Sockets | real loopback listeners: port probe, SOCKS5 probe against an in-process server, the traffic bridge (byte counts, half-close, concurrency, teardown) |
| SQLite | real files in a temp folder: migrations, upgrade, corruption recovery, retention, crash recovery, exports |
| Configuration | round trips, corrupt/partial/newer/older files |
| Localization | key/placeholder/access-key parity, untranslated detection, plural rules, source scan for referenced keys, no hardcoded XAML text |

What is **not** automated: rendering and behaviour of the WPF windows, the notification-area icon, balloon notifications,
the Run-key write, and the Windows job object assignment (a Windows-only test covers the latter on CI). Those need a real
Windows desktop.

Tests never depend on a real SSH server and no credentials are used in CI. Avoid sleeping in tests: use `TestWait.Until`, the
`FakeClock`, or completion signals.

## Verification status of the original implementation

The first complete implementation (v0.1.0–v1.0.0) was written on a headless Linux host. Per the specification (§70) its
author did not and could not visually test the GUI. State machines, supervision, reconnect, argument generation, rate
calculations, database migrations, retention, exports, localization and validation have unit tests; the WPF application was
compiled and published for `win-x64` but not executed. Treat the Windows-specific code as "reviewed and compiled" until it has
been exercised on a real machine, and fix what you find.

## Adding things

- **A localized string**: add the key to both `Localization/Strings.en.json` and `Strings.ru.json` (the tests fail if one is
  missing, a placeholder differs, or the Russian text is just a copy), and use it through `ILocalizer` or `{loc:Loc key}`.
- **A failure code**: add the rule to `FailureClassifier` (or create it where it occurs), then `failure.<code>` in both languages.
- **A validation code**: emit it from `ProfileValidator`, then `validation.<code>` in both languages; map the field in
  `SettingsDraft` so the dialog shows it next to the right input.
- **A configuration setting**: add the property with its default, validate it, expose it in `SettingsDraft`, the settings dialog and
  `docs/CONFIGURATION.md`. If an existing file could change meaning, bump `AppConfig.CurrentSchemaVersion` and add a `ConfigMigration`.
- **A database change**: append a `Migration` to `SchemaMigrations.All` (never edit an old one) and add a test that upgrades an
  old-version database.
- **A traffic backend**: implement `ITrafficMonitor`; report `null` totals if you cannot measure accurately.

## Versioning

Semantic Versioning, `MAJOR.MINOR.PATCH`. The version is defined once, in `Directory.Build.props`, and flows to the assembly
version, About, diagnostics and `--version`. Git tags are `vMAJOR.MINOR.PATCH` and must match it (`release.yml` checks).
Commits use [Conventional Commits](https://www.conventionalcommits.org/).
